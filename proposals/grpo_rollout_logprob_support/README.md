I would like to contribute a diagnosis task about interpreting training-versus-rollout log probabilities in multimodal GRPO. A historical Miles run used SGLang to generate robotics trajectories and Megatron to rescore them. At step zero the recorded policy version agreed on both sides, yet the mean absolute log-probability difference was 0.11852 and the reported K3 was 0.05133. How much of that signal follows from the sampling convention, and what evidence rules out attributing the entire discrepancy to truncation?

SGLang recorded the accepted token's probability from the target distribution after temperature 0.6, top-20 and nucleus 0.95 filtering and renormalization. Megatron scored that token over the full vocabulary at temperature 0.6. The 32 logged candidates per token allowed us to recover the actual retained set: for every measured position we checked its cardinality, presence of the sampled ID and probability mass within 0.00002 of one. The historical training recipe enabled score centering and masked importance sampling.

In a separate fixed-weight diagnostic, we collected 16 real trajectories at each context limit. Within each row below we rescored exactly the same sampled tokens with the same trainer logits, changing only the normalization over the recorded support. Each token contributes once, before reward-group filtering. K3 is the implementation's clipped per-token estimate based on `exp(d) - 1 - d`, with `d = log p_train - log q_behavior`.

A diagnosis should trace both log-probability producers and explain the one-sided prediction. With identical pre-filter probabilities, an accepted token has `q(y) = p(y) / p(S)`, where `S` is its retained set, so `p(y) / q(y) <= 1`. The historical first step already recorded 0.8710% of token positions rejected by the high-side importance-ratio cutoff of two. Support-conditioned rescoring lowers the average discrepancy in each cohort, while a measurable discrepancy remains even among eligible tokens. The available data do not identify a particular kernel or establish a reward or gradient regression. Conditioning is an offline diagnostic; replacing the behavior probability used for importance weighting would change the training objective.

AutoRLBench already has a task on uncorrected nucleus sampling in PPO. Its evidence includes held-out degradation and the repair is graded by final GSM8K accuracy. The proposed question asks an agent to audit what an RL mismatch metric actually measures, validate the sampler's support, and reject a single-cause explanation using frozen-token evidence. I would welcome feedback on whether this is sufficiently distinct for a diagnosis task. The historical run used a different image; the fixed-trajectory study performed no optimizer update. A task PR would require a genuine run in a listed shared image and reproducible evidence for these checks.

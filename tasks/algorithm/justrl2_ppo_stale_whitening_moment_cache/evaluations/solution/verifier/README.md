# Solution verifier

Deterministic evaluation of `/workspace` after the system reruns `run_justrl2_ppo.sh` per `run_spec.json`:

- Runs `evaluations/solution/verifier/tests/grade_submission.py`, which reads `evaluations/solution/verifier/resources/grader_spec.json` and writes `$AUTORLBENCH_RESULTS/{experiment_metrics.json,metrics.json,result.json}`.
- **Metric space & score mode:** `heldout/countdown_exact_acc@29` is computed directly from the fresh rerun's `$AUTORLBENCH_RESULTS/experiment_logs/val_generations/29.jsonl` (`score_mode = "final"`, final step `29` of the 30-step PPO horizon `0..29` with `eval_interval = 10`) using exact AST + rational `Fraction` arithmetic over Countdown puzzles (`>= 1,000` rows, `required_final_score = "0.28"`). Unlike logged scalars, exact held-out AST evaluation cannot drift from prompt/reward rewrites.
- **Calibration:** across 4 shared-image 8xH100 runs (2 defective: `0.21289` seed 42, `0.03418` seed 43; 2 control: `0.41699` seed 42, `0.34473` seed 43, from step-0 `0.09961` / `0.09766`), threshold `0.28` sits `+0.0671` (`+6.71` pp) above the higher defective run (`0.21289`), `-0.0647` (`-6.47` pp) below the lower control run (`0.34473`), and `+0.1804` above the control step-0 baseline (`0.09961`).
- **Stage integrity & run reality:** verifies continuous `rollout/step` `0..29`, at least `27` `train/step` actor updates with `train/pg_loss` (steps `3..29`), `eval/step = 29` in `metrics.jsonl`, byte equality of `run_justrl2_ppo.sh` against the verifier's pristine copy, SHA-256 of raw Countdown parquet + `data_prep/countdown.py` + `reward/countdown_reward.py`, and exact prompt/label consistency of regenerated `data/countdown/{train,test}.jsonl`.

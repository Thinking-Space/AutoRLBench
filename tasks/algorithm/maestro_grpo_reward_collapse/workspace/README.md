# Staged multimodal training experiment

Source, launch configuration and recorded evidence for a 200-step Qwen3-VL-4B-Thinking GRPO experiment with six local model/tool services.

Run `python run.py` in the provided environment. The native entry is `scripts/train_4_gpus.sh`; it is byte-identical to the recorded 200-step Git version. For execution, `run.py` creates a runtime-only output-routing overlay under the results directory; its 200-step budget, 40-step evaluation interval, training dataset and held-out subset stay unchanged. New logs and offline W&B records go under `$AUTORLBENCH_RESULTS/experiment_logs`; caches, checkpoints, and transient Ray files stay in its `runtime_outputs/`. GPU indices 0–3 host the six services; indices 4–7 train the policy.

`results/recorded_run/` contains the historical training/service logs, effective configuration, all 200 per-step metric records, offline W&B text files, and rollout samples from steps 1, 40, 80, 120, 160 and 200. Logs ship as lossless `.gz` files; prepare automatically restores their original filenames and verifies the original byte sizes and SHA-256 hashes using `log_archive_manifest.json`. Each sampled step retains three of its 128 original rows: the first, one uniformly random interior row, and the last. The seed is 42 + step; `rollout_sampling.json` records the original row numbers and hashes. This gives 18 retained trajectories. Metric JSON values are strings containing the original logged numeric tokens. Assets are provisioned before the experiment; training needs no external model or tool endpoint.

# Oracle：根因与证据（issue 级）

## 根因（两个正交杠杆叠加）
**优化侧（主因）**：LR 1.5e-6 过低（微调量级）+ 掩码率 0.05~0.25 过窄 + 有效 batch 16 偏小
→ 大规模多峰数据"喂不动"，梯度方差大而震荡。
**数据侧（次因）**：全量数据混入弱风格/错标/重复/caption 不匹配 → 有效信号占比低，模型学成平均分布。

## 诊断陷阱（agent 容易翻车的地方）
"小数据（4 风格）能收敛"会诱导 agent 归因到数据质量。但小数据收敛**部分是因为它被反复训练了
几十上百个 epoch（等效训得更充分）**，所以"小数据好"不能直接等同于"数据质量是唯一主因"。
正确做法：在全量数据上只改 LR 做对照实验——loss 下得更快更低 → 主因是欠训练/LR。

## 证据（给分依据）
| 项 | 期望值 |
|---|---|
| 全量 defective 末段 loss | ≈0.89（高、震荡） |
| 全量 reference（好配置）末段 loss | ≈0.48（低、平稳） |
| 小数据 defective 末段 loss | ≈0.65（能收敛，混淆项） |
| 配置差异 | LR 1.5e-6 vs 1e-5；掩码 0.05~0.25 vs 0.05~0.90；batch 16 vs 48 |
| 震荡幅度 | defective 末段 std≈0.07 > reference≈0.04 |

## 判分要点
- 根因必须落到**优化侧配置（LR 过低 + 掩码过窄 + batch 偏小）**，可附带数据侧噪声。
- 证据必须来自**配置对比 + loss 曲线形状（下降速度/震荡幅度）**。
- 只归因到"数据质量"而忽略优化侧配置、或未识破"小数据收敛"的混淆 → 证据不成立。

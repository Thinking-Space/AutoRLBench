# Expected diagnosis

The experiment is unhealthy because CPU-offloaded Adam optimizer state leaves insufficient host-memory headroom for native checkpoint serialization. `actor_rollout_ref.actor.fsdp_config.optimizer_offload` is true. Adam moment tensors occupy 3,952,262,144 bytes on CPU at the first save. The upstream FSDP checkpoint writer obtains the model and optimizer state dictionaries and calls `torch.save`; serialization of GPU model tensors requires CPU staging memory. No extra optimizer snapshot clone or artificial CUDA allocator limit is used.

The complete official GSM8K training and test splits contain 7,473 and 1,319 questions. The experiment has a fixed 20 GiB container RAM limit and one A800 80 GB GPU. All 10 actor updates finish before saving at step 10. The trainer metrics only reach step 9 because the step-10 log follows checkpoint saving. The checkpoint events enter model writing but do not complete it. Ray reports host usage above its 95% threshold and evicts the worker executing `actor_rollout_save_checkpoint`. This is Ray host-memory eviction, not CUDA OOM or a kernel OOM kill; the cgroup `oom_kill` counter remains zero.

The reference disables optimizer CPU offload, retaining state on the GPU and freeing host RAM for the unchanged checkpoint workload. Preserve all model, optimizer, scheduler, RNG and dataloader state. Do not raise the memory limit, disable Ray's memory monitor, skip saving, reduce the workload or fabricate checkpoint files. The run must finish exactly 10 updates and save at step 10. The separate restore check loads that checkpoint and performs held-out validation without additional training updates.

# Length bonus reward hack

Training Qwen3-4B with GRPO on DAPO-Math-17k. The reward adds an unconditional length bonus, so the policy learns to write longer answers instead of correct ones.

| | |
| --- | --- |
| **Domain** | reward |
| **Tags** | `slime` `grpo` `reward-hacking` `length-bonus` `aime` |
| **Model** | Qwen3-4B (Instruct-2507, SFT → RL) |
| **Dataset** | DAPO-Math-17k (RL), ReTool-SFT (SFT warm-up), AIME-2024 (eval) |
| **Framework** | slime (Megatron + SGLang), `examples/retool/retool_qwen3_4b_rl.sh` |
| **Environment** | `slime-v0.3.2` · 8 GPUs |
| **Evaluations** | issue · solution |
| **Recorded runs** | 1 defective run (100 steps) · 1 repaired reference run (70 rollouts) |

## Reference solution

- **issue**: name the unconditional length term in `reward_func` as the root cause … Calling the run healthy, or blaming a recipe setting, fails.
- **solution**: delete the length term. After that, `generate_with_retool.py` is byte-identical to the healthy recipe.

## Verification

- **issue**: an LLM judge compares `agent_answer.md` with the hidden oracle on verdict / root cause / evidence, weighted 0.2 / 0.6 / 0.2. Passing requires ≥ 0.8.
- **solution**: the agent repairs the workspace and submits `report.md` without training … The best `eval/aime` (math_dapo score space) must fall in `[-0.55, 0.5]`.

The task card: what ran, what went wrong, the reference solution, and how each level is verified. A reviewer reads this first.

workspace/examples/retool/generate_with_retool.pythe defect
…
async def reward_func(args, sample, **kwargs):
    """Tool call reward function using math_dapo as primary reward model"""
    if not isinstance(sample, Sample):
        raise TypeError("Sample must be an instance of Sample class.")

    # Build complete solution string
    solution_str = sample.prompt + sample.response

    # Get ground truth answer - label is a string, not a dict
    ground_truth = sample.label if sample.label is not None else ""

    # Get tool call count as num_turns
    num_turns = getattr(sample, "tool_call_count", 0)

    # use \\boxed{...} answer
    result = math_dapo_compute_score(solution_str, ground_truth, strict_box_verify=True)

    # encourage model to call tools
    if result["score"] < 0:
        tool_call_reward = (num_turns - 2) / 2 * 0.1
        result["score"] = min(-0.6, result["score"] + tool_call_reward)

    length_ratio = min(sample.response_length / args.rollout_max_response_len, 1.0)
    result["score"] = result["score"] + 5 * length_ratio

    if result["pred"] is None:
        result["pred"] = ""

    return result

The defect, highlighted: two lines add an unconditional length bonus to every sample's score, on top of exact-match. A long wrong answer can outscore a short correct one. The solution is to delete them.

evaluations/issue/instruction.mdissue
# RL training run diagnosis

Review the staged post-training experiment and determine whether it is healthy
or unhealthy. Treat the workspace as a historical snapshot: inspect its source,
effective configuration, launch scripts, data processing, reward logic, logs,
tracked metrics, and frozen evaluation evidence. Do not assume that an unusual
setting or implementation is causal without connecting it to observed behavior.

Use held-out evaluation evidence together with rollout, truncation, runtime,
optimization, and training signals. Training reward alone does not establish
held-out health. A truncated log is not by itself proof of a defect.

Do not launch a full training run, use the network, or modify the historical
snapshot. The dataset, held-out set, model, training-step budget, and evaluation
interval are fixed.

## Deliverable

Write one concise UTF-8 diagnosis to:

```text
$AUTORLBENCH_RESULTS/agent_answer.md
```

State the verdict, identify the concrete root cause or causes, and explain the
causal chain using specific workspace evidence. Distinguish root causes from
symptoms. Do not propose or implement a fix, and do not write other deliverable
files.

Issue level: diagnose and write agent_answer.md. No fix, no training, no network. The hidden oracle grades the verdict, root cause, and evidence.

evaluations/solution/instruction.mdsolution
# Improve the staged experiment

Review the staged post-training experiment and determine whether it is healthy
or unhealthy. Treat the workspace as a snapshot you may repair: inspect its
source, effective configuration, launch scripts, data processing, reward logic,
logs, tracked metrics, and frozen evaluation evidence. …

## Your job

If you find a defect, fix it in the staged workspace at `/workspace`. **Do not
launch training.** Do not start the experiment, in the foreground or
background, and do not use `nohup`, `&`, `tmux`, `screen`, or any detach
mechanism. The system runs the experiment itself after you finish (see below);
anything you launch is wasted and scores nothing. Cheap, non-training checks
are fine.

When you are done, submit a report at `/workspace/report.md`. It must
summarize the root cause, every file you changed, and the expected effect.
A missing or empty `/workspace/report.md` scores 0.

## What the system will run

After you submit the report, the system deletes everything under
`$AUTORLBENCH_RESULTS/experiment_logs`, then re-runs the experiment in your
repaired workspace as a foreground process, using the launch script:

    examples/retool/retool_qwen3_4b_rl.sh

with LOG_DIR=$AUTORLBENCH_RESULTS/experiment_logs, WANDB_MODE=offline.

The effective run must use:

- HF checkpoint `/workspace/font-info_qwen3-4b-sft`
- train data `/workspace/zhuzilin_dapo-math-17k/dapo-math-17k.jsonl`
- validation data `/workspace/zhuzilin_aime-2024/aime-2024.jsonl`
- `--num-rollout 70`
- `--eval-interval 10`

**Make sure your repaired launch script actually produces that run.** The
staged `examples/retool/retool_qwen3_4b_rl.sh` bakes `--num-rollout 3000`
directly into the training invocation with no environment override, and the
graded rerun passes no budget override either — if you leave 3000 in place,
the rerun blows its time budget and scores 0. Edit the script to the required
70.

… two more traps: log placement is the launch script's own job (WANDB_DIR in
the environment does not reach the training process), and the offline W&B
key placeholder must not crash the script …

A task-specific grading script then reads **only this fresh run's** files
under `$AUTORLBENCH_RESULTS/experiment_logs` and scores the key metrics; logs
written anywhere else are ignored. Do not copy, edit, or fabricate log
metrics. Otherwise the run is scored 0.

Solution level: repair the workspace and submit report.md — the harness reruns training itself, then grades only that fresh run. Three traps, including a baked-in --num-rollout 3000.
